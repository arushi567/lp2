# 🐍 STEP 9 — BACKEND CODE (FLASK APP)

```bash
nano main.py
```

---

## Paste:

```python
from flask import Flask, render_template, request, redirect

app = Flask(__name__)

tasks = []

@app.route("/")
def home():
    return render_template("index.html", tasks=tasks)

@app.route("/add", methods=["POST"])
def add():
    task = request.form.get("task")
    if task:
        tasks.append(task)
    return redirect("/")

@app.route("/delete/<int:index>")
def delete(index):
    if 0 <= index < len(tasks):
        tasks.pop(index)
    return redirect("/")

if __name__ == "__main__":
    app.run()
```

---

### 👉 Why this backend exists:

| Part       | Meaning           |
| ---------- | ----------------- |
| tasks = [] | temporary storage |
| / route    | homepage          |
| /add       | add task          |
| /delete    | remove task       |

# ☁️ 📘 THEORY — GOOGLE APP ENGINE (VERY IMPORTANT FOR VIVA)

---

# ☁️ 1. CLOUD COMPUTING (BASICS THEORY)

📌 Definition:
Cloud computing is the delivery of computing services like servers, storage, databases, networking, and software over the internet on a pay-as-you-use basis.

---

## 📌 Key Characteristics:

* On-demand self service → resources can be created anytime
* Broad network access → accessible over internet
* Resource pooling → shared infrastructure among users
* Scalability → resources can increase or decrease automatically
* Pay-as-you-go → pay only for usage

---

## 📌 Types of Cloud Models:

### 1. Public Cloud

Shared infrastructure provided by companies like Google, AWS

### 2. Private Cloud

Dedicated cloud for one organization

### 3. Hybrid Cloud

Combination of public + private cloud

---

## 📌 Service Models:

### 1. IaaS (Infrastructure as a Service)

* Provides virtual machines, storage, networks
* Example: EC2

### 2. PaaS (Platform as a Service)

* Provides platform to deploy apps without managing servers
* Example: **Google App Engine**

### 3. SaaS (Software as a Service)

* Ready-to-use software
* Example: Gmail, Google Docs

---

# ☁️ 2. GOOGLE CLOUD PLATFORM (GCP)

Google Cloud Platform

📌 Definition:
Google Cloud Platform is a suite of cloud computing services that runs on the same infrastructure Google uses internally.

---

## 📌 Features:

* High scalability
* Global infrastructure
* Secure and reliable
* Pay-per-use pricing
* Managed services available

---

# 🚀 3. GOOGLE APP ENGINE (MOST IMPORTANT)

Google App Engine

---

## 📌 Definition:

Google App Engine is a **Platform as a Service (PaaS)** that allows developers to deploy applications without managing servers or infrastructure.

---

## 📌 Simple Meaning:

You just write code → Google handles everything else:

* servers
* scaling
* deployment
* load balancing

---

## 📌 Why it is called PaaS?

Because it provides:

* runtime environment
* deployment tools
* automatic scaling
  without giving OS or server control

---

## 📌 Key Features:

* Fully managed platform
* Automatic scaling
* No server management required
* Built-in load balancing
* Supports multiple languages (Python, Java, Node.js)

---

## 📌 Advantages:

* Very fast deployment
* No infrastructure setup
* Highly scalable
* Secure and managed by Google

---

## 📌 Disadvantages:

* Less control over OS
* Limited customization compared to EC2
* Vendor lock-in (depends on Google ecosystem)

---

## 📌 Use Cases:

* Web applications
* Mobile backend services
* APIs
* Scalable business apps

---

# 🧠 4. APP ENGINE ARCHITECTURE

User Browser
↓
Google Frontend (Load Balancer)
↓
App Engine Service
↓
Application Code (Flask / Python)
↓
Response returned

---

## 📌 Explanation:

* User sends request via browser
* Google routes it to App Engine
* App runs in managed environment
* Response is sent back

# 📁 5. APP.YAML (CONFIGURATION FILE THEORY)

📌 Definition:
`app.yaml` is a configuration file used to define how the application should run on App Engine.

---

## 📌 Purpose:

* Defines runtime environment
* Defines entry point
* Maps URL handlers

---

## 📌 Example:

```yaml
runtime: python311
entrypoint: gunicorn -b :$PORT main:app
```

---

## 📌 Meaning:

* runtime → Python version
* entrypoint → how app starts
* $PORT → dynamic port assigned by Google

---

# ⚙️ 6. GUNICORN (IMPORTANT THEORY)

📌 Definition:
Gunicorn is a production-grade WSGI server used to run Python web applications.

---

## 📌 Why needed?

Because:

* Flask development server is not production-ready
* Gunicorn handles real traffic
